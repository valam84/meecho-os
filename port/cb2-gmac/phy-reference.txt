Эталон: расширенные регистры YT8531 под работающей системой
==============================================================

Снято 2026-09-08 с CB2 под вендорским ядром 6.1.115-btt-rockchip64 (Armbian),
линк 100 Мбит/с full duplex, eth0 8a:6e:41:09:8e:2f. Инструмент —
port/cb2-gmac/phyext.py: SIOCGMIIREG/SIOCSMIIREG через страничное окно
0x1e/0x1f, как это делает сам драйвер PHY.

Зачем: mainline motorcomm.c для phy-mode "rgmii" выключает внутренние
задержки PHY (0xa001 бит 8, поля 0xa003). Плата же живёт под вендорским 6.1,
чей yt8531_config_init задержки не трогает и вместо этого пишет аналоговую
часть. Наш драйвер повторял mainline — приём работал, передача до провода не
доходила: полная развёртка задержки GRF (0x00..0x7f), все четыре селектора
такта и подмена MAC ничего не дали. Повторение вендорской последовательности
регистр в регистр дало передачу с первого прогона.

  phy addr 0 id 4f51e91b
  std: r00=1140 r01=796d r04=1de1 r05=51e1 r06=0007 r09=0300 r0a=0000 r11=7c40

  ext 000c = 8000
  ext 0027 = e810      (у MEECHO читается e812 - бит 1 меняется сам, статус)
  ext 0057 = 274c      BGS-напряжение передатчика 100M: вендор ставит [11:8]=7
                       вместо заводских 9 ("0x294c -> 0x274c"), без объяснения
  ext a000 = 0000
  ext a001 = 8100      RXC_DLY_EN (бит 8) ВКЛЮЧЁН - заводское, вендор не трогает
  ext a003 = 00f1      задержки RGMII заводские: RX 0, TX 100M 0xf, TX 1G 0x1
  ext a010 = dbcf      сила выходов RXC / PHY_CLK_OUT / RXD (вендор)
  ext a012 = 00d0      PHY_CLK_OUT 125 МГц включён - это такт передачи SoC
                       (clock_in_out = "input")
  ext a039 = bf00      скважность RXC, блок из вендорского драйвера:
  ext a03a..a03f = 9696   (0x9696 = "nodelay duty", для rgmii-id было бы 0x4040)
  ext a040 = ffff
  ext a041 = 00ff

Вендорский yt8531_config_init (drivers/net/phy/motorcomm.c,
bigtreetech/linux-rockchip, ветка bpi-rk-6.1-rkr5.1; копия -
ref/vendor-motorcomm.c, GPL, только для чтения):

  write_ext(0xa012, 0xd0)              PHY_CLK_OUT 125M
  write_ext(0xa040, 0xffff)
  write_ext(0xa041, 0xff)
  write_ext(0xa039, 0xbf00)
  write_ext(0xa03a..0xa03f, 0x9696)    RXC duty, nodelay
  write_ext(0xa010, 0xdbcf)            drive strength
  ext(0x57) = (ext(0x57) & ~0xf00) | 0x700   BGS 100M

Драйвер MEECHO (dwmac_mdio.c, yt8531_config) делает ровно это и печатает при
старте все регистры из таблицы рядом с эталоном, помечая расхождения словом
DIFFERS. Первый прогон с этой настройкой (port/phyref.log): все совпали,
кроме 0x27 (e812 против e810, статусный бит).

Второй дефект, вскрывшийся сразу после (передача заработала, а пинг 1 из 8):
приём стоял на дескрипторе 49 - драйвер инвалидировал строку кэша группы
дескрипторов только на входе в группу, и дескриптор, найденный один раз "ещё
за устройством", читался потом из кэша навсегда. Починено в dwmac_ring.c;
третий прогон (port/phyref2.log): 20 из 20, 0% потерь, 182 принято, 73
отправлено, ошибок 0; на хабе tcpdump видел 54 кадра от 02:00:fe:01:00:00.
