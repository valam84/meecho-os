# Экран CB2: эталон и как его снимать

Всё здесь снято с вендорского Linux на плате (6.1.115-btt-rockchip64) до
того, как был написан драйвер `minix/drivers/video/fb/arch/aarch64/`.

| Файл | Что |
|---|---|
| `capture.sh` | снимок конвейера только чтением: debugfs драйверов vop2 и dw-hdmi (PHY — через его I2C), такты, домен питания, GRF/CRU/PMUCRU/PMU через `/dev/mem` |
| `ref-720p-forced.txt` | снимок при включённом разъёме, 1280x720@60 — эталон |
| `ref-disconnected.txt` | тот же снимок с выключенным разъёмом, для сравнения |
| `live.dtb` | дерево работающей системы (оверлей `hdmi` наложен) |
| `vop2-recipe.md` | каждое записываемое слово VOP2 с расшифровкой полей и сверкой со снимком |
| `ref/` | откуда взяты номера регистров (сами исходники — вне git) |

Снимать заново (плата под Armbian, по ssh):

    echo on > /sys/class/drm/card0-HDMI-A-1/status   # если монитора нет
    sh capture.sh > snapshot.txt
    echo detect > /sys/class/drm/card0-HDMI-A-1/status

Без монитора драйвер Linux поднимает конвейер только с принудительно
включённым разъёмом; EDID нет, режим — 1280x720@60.

Что на экране MEECHO, без монитора читается так (утилиты в
`port/test/fb/`): на плате `fblog` — журнал драйвера и живое состояние
(HPD, PLL PHY, строка развёртки, счётчики консоли), `fbpeek N` — строка N
консоли из памяти кадра знаками, а на хосте `fbocr.py` переводит вывод
`fbpeek` обратно в текст тем же шрифтом.
